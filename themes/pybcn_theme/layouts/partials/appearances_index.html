{{- /* The pages each person appears on, inverted from the pages themselves. Returns a map from person id to a list of appearances, each a dict with label, title, url, year, type, ord, date, and end_date. No argument is read: the data comes from site.RegularPages and from data/roles.yaml. date and end_date are the two fields of the page as the front matter writes them, unparsed, so the Events table of a person page can set the month and the day of an event in columns through partials/event_date.html (cached by the URL of the page, the key the listings use) without reading the page again. Empty on a page with no year, and on the one edition that carries no date. type is the event type of the page, a key of data/event_emoji.yaml through partials/event_type.html, and it is set only on a page with a year, which is what the rows of /events/ and /people/ call an event. A page with no year (the organizers pages) carries an empty type: its marker is the glyph of the role, not of an event. The type is resolved here, in the one walk, because the row of /people/ reads the index and not the page, and the walk already holds the page; resolving it from the URL again in the layout would be a second walk of the site per row. Call it through partialCached with a constant variant, so the site is walked once per build and not once per person page: partialCached "appearances_index.html" site "appearances-index" Two front matter shapes list people by hand. An event page has people_sections, each with a title and a list of levels. An association page has people_levels, each with a name. A level entry is a bare id, or a map with an id when the page overrides the role for that entry (see people-grid.html). A third shape credits people without a list of its own. Every talk of the talks block carries speakers, a list of person ids, and whoever gave a talk was at that event. A talk is a record of the day itself, so its speakers index like a curated entry, under the heading "Speakers". The curated lists are the only source for the two pages with no year and the only source of the other roles; the talks are the only source for the three editions that carry a programme and no people_sections, PyData Barcelona 2017, PyDay BCN 2018, and PyDay BCN 2019. The heading is the level name when the level has one, and the section title when it does not. The Django page has one section titled "Mentors, speakers & volunteers" with three named levels, Mentors, Speakers and Volunteers. Indexing the section title made everyone in it a Volunteer; the level name says which of the three each person was. The Speakers and Organizers sections of the event pages have one level each and no level name, so they fall back to the section title. Every person a page lists, and every person a talk credits, is indexed. The index used to cover the people listed on /pybcn_association/organizers/ and nobody else, because every other person was a speaker or a volunteer of one event, whose page would list that one event and nothing else. The talks ended that: 353 people gave at least one talk, over 544 pairs of a person and an event, so the page of a speaker now reads as the history of the days they spoke at. The meetups of the Archive widened it again, from 134 people and 160 pairs. The heading goes through data/roles.yaml, which turns "Speakers" into "Speaker". The heading itself is the fallback, so a new heading shows up unmapped rather than not at all. An appearance is one (heading, page) pair. The same person can be listed twice on a page under one heading, by two entries, by a level with no name that repeats the section title, by two talks of the same day, or by a curated Speakers level and a talk of the same page, and the page would then link that page twice under one label. The talk heading is "Speakers", the heading the curated level of an event page already carries, so a speaker the page lists by hand and credits with a talk reaches one label and is kept once. Two different headings on one page stay two appearances: Ferran Jovell is a Mentor and a Speaker of the Django page, and an organizer who gave a talk is an Organizer and a Speaker of that edition, and the page lists the event once with both roles (see person_appearances.html). Drafts are skipped by name as well: site.RegularPages drops them in a normal build, but a server run with -D would index content/canary.md. */ -}} {{- $index := dict -}} {{- range $pg := site.RegularPages -}} {{- if $pg.Draft }}{{ continue }}{{ end -}} {{- /* heading -> list of ids, in the order the page lists them */ -}} {{- $headings := slice -}} {{- range $pg.Params.people_sections -}} {{- $title := .title -}} {{- range .levels -}} {{- $headings = $headings | append (dict "heading" (default $title .name) "ids" .people) -}} {{- end -}} {{- end -}} {{- range $pg.Params.people_levels -}} {{- $headings = $headings | append (dict "heading" .name "ids" .people) -}} {{- end -}} {{- /* The speakers of every talk of the page, as one more heading, and last: the curated headings keep the ord they have today, and the lists of a page with no year keep the order that page gives them. A talk with no speaker, which is eleven of the fifteen talks of PyDay BCN 2019, adds nothing, and a page with talks and no speaker at all adds no heading. */ -}} {{- $speakers := slice -}} {{- range $pg.Params.talks -}} {{- range .speakers -}} {{- $speakers = $speakers | append . -}} {{- end -}} {{- end -}} {{- with $speakers -}} {{- $headings = $headings | append (dict "heading" "Speakers" "ids" .) -}} {{- end -}} {{- if not $headings }}{{ continue }}{{ end -}} {{- /* The event type of the page, once per page and not once per person it credits. event_type.html reads the folder of the file, so a page with no file (none today) gets no type. */ -}} {{- $type := "" -}} {{- if and $pg.Params.year $pg.File -}} {{- $type = partial "event_type.html" $pg -}} {{- end -}} {{- $seen := dict -}} {{- range $ord, $h := $headings -}} {{- $heading := $h.heading -}} {{- $label := default $heading (index site.Data.roles $heading) -}} {{- range $h.ids -}} {{- $id := . -}} {{- if reflect.IsMap . }}{{ $id = .id }}{{ end -}} {{- $key := printf "%s|%s" $label $id -}} {{- if index $seen $key }}{{ continue }}{{ end -}} {{- $seen = merge $seen (dict $key true) -}} {{- /* ord is the position of the heading in the page. It orders the headings of a page with no year, where there is no date to sort by: the levels of organizers.md are listed current board first, and the list has to read that way rather than alphabetically, which put the 2018 board above the current committee. */ -}} {{- /* appearances_title, when the page sets one, is the name this list calls the page by. A page title says what the page is, and a line of this list says where a role is held, which is not the same words: /pyladies_bcn/organizers-and-speakers/ is titled "PyLadies BCN Organizers", and the line reads "Organizer at PyLadies BCN". Without it the line repeats the role in the name of the page it links to. */ -}} {{- $entry := dict "label" $label "title" (default $pg.Title $pg.Params.appearances_title) "url" $pg.RelPermalink "year" (int (default 0 $pg.Params.year)) "type" $type "ord" $ord "date" (default "" $pg.Params.date) "end_date" (default "" $pg.Params.end_date) -}} {{- $index = merge $index (dict $id (append $entry (default slice (index $index $id)))) -}} {{- end -}} {{- end -}} {{- end -}} {{- return $index -}}
