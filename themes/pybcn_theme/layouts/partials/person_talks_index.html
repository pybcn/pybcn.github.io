{{- /* The talks each person gave, as talk pages, inverted from the pages themselves. Call it through partialCached with a constant variant, so the site is walked once per build and not once per person page: partialCached "person_talks_index.html" site "person-talks-index" Why a second index next to appearances_index.html. The appearances index answers "which pages credit this person, under which heading", and it has one row per heading and page, so a person who gave two talks on one day is one row there. The page of one person lists the talks themselves, each as a link to its talk page, which is a different question: one row per talk, with the day it was given. The talk pages carry the two ids and no copy of the record (see content/talks/_content.gotmpl), so each one is resolved through partials/talk_record.html, which is cheap and no longer cached (its header says why: Hugo's partialCached holds 1000 entries, and a key per talk was most of them). The photos and the video of a talk come from the same record, so the page of a person with two photographed talks at one event gets both, and a talk with two photographs gets both as well (the record carried the first photo only until 2026-10-15). An index keyed by person and event, talk_photos_index.html, gave the modal of a person card one thumbnail per event row; the modal and that index are gone (see people_summary.html). A talk with no speaker indexes nothing. A speaker id with no record is indexed all the same, and no page reads it: the page of a person is rendered from a record, so an id with none has no page to print the list on. bin/check-content fails the build for the broken reference. Drafts are skipped by name as well, as in appearances_index.html: site.RegularPages drops them in a normal build, but a server run with -D would index content/canary.md.
