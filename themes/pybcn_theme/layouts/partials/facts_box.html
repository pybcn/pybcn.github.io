Argument: a dict with items, a slice of dicts, each with: label the word of the row: "Speaker", "Venue" value the fact. A plain string is escaped by the template, as content always is here. The output of a partial, partials/person_page_link.html for a name or the html of partials/event_date.html for a day, is HTML a template of this theme already escaped, and prints as it is. No content field reaches this partial through safeHTML (AGENTS.md). values instead of value: a list, joined here with ", " and " and " the way partials/agenda_entry.html joins the names of a session. Each element prints as a value does, so a list of links stays a list of links; a caller that joined them with delimit would get a string, which the template escapes. url optional. The value then prints as a link to it, with the value as the text, so a caller never builds the anchor and the text is escaped here like any value. icon optional, a Font Awesome class: fa-user. The glyph is decoration, aria-hidden, because the label next to it says the same thing in words (the rule of partials/event_type_icon.html for an icon with its label beside it). A row with no icon keeps its place in the column. A class that starts with icon_ is one of the masks of main.scss and not a Font Awesome glyph, so it prints on its own: icon_x is the X mark, which the Source row of a talk read from a post on X took, because every link to x.com carries it. mark_url optional, instead of icon: the URL of an outbound link, whose host picks the glyph through partials/link_mark.html, the one mark per destination the whole site prints. The Source row of a talk and of a meetup pass the URL of the value, so the row carries the mark of Meetup, of X, or the generic one. note optional, a sentence that explains the value, kept behind a disclosure, with: note_label the words of the disclosure: "Who is counted". Set it on every row that carries a note, because a page may hold two and a screen reader lists them by name. lang optional, the language of the value when it is not English, printed on the dd (WCAG 3.1.2). meta optional, a Pagefind meta spec for the dd, "speakers" or "venue": the text of the value is returned with the search result under that key. See below. filter optional, a Pagefind filter spec for the dd, "lang" (the text of the value) or "year:2019" (inline). ignore optional, true to keep the row out of the search index: the type of a talk, its length, the record it was read from, which are the same words on every page. The search. The box sits inside the element the layout marks as the search body of the page (data-pagefind-body, see partials/hero_header.html), so its values are what a reader searches: the names of the speakers, the venue, the RSVPs. Three things in it are not. The dt is the label, "Venue" on 281 pages, and is ignored; a row the caller marks ignore is ignored whole; and the note behind the disclosure is a sentence this site wrote, the same on every page that has it, and is ignored. A filter inside an ignored row still applies, which is how the group of a meetup is a filter value and not a searchable word. Pagefind joins the text of adjacent elements with no space between a dt and a dd, so the label would also stick to the value ("VenueCahootCoworking") if it were indexed; ignoring it is what keeps the value a word. An item with no value is left out, so a caller may pass every fact it knows the name of and the box prints only the ones the record holds. Nothing reads "unknown" and nothing reads "0": that is the rule of layouts/_default/meetup.html and layouts/people/list.html, and this partial keeps it for every caller. A box with no row prints nothing. The shape: a description list. The content is pairs of a label and a value, which is what dl, dt and dd are for, and a screen reader announces the pair as a term and its description and gives the count of rows up front; a ul of "Label: value" strings would read the colon aloud or lose it, and a table of two columns would announce a header the box does not have. Each pair sits in a div, which the HTML standard allows inside a dl, so the pair is one element to style; the div is display: contents in facts.scss and the dt and dd land in the two columns of the grid of the dl, the label column as wide as its longest label. At 390px the two columns still fit: the longest label, RSVPs, takes about a third of the width, and a long value wraps inside its cell. The box is the bordered pill of partials/count_card.html at full width, in the color of the facts, so the two read as the same kind of thing: a box of figures. The icons are Font Awesome and not emoji, one per line. The site already keeps three vocabularies of glyph with one job each: an emoji is the type of an event (data/event_emoji.yaml, the rows of /events/ and /people/), a Font Awesome icon is a count (partials/count_card.html) or a type of session (the program grid, partials/event_types.html), and a Font Awesome brand mark is where a link goes (partials/person_social_icons.html). An emoji per fact would be a fourth, and it would sit on the page of a person next to the count card, whose icons are Font Awesome, with the two sets meaning the same kind of thing in two alphabets. The type row of a talk takes the icon of its type from partials/event_types.html, the glyph the grid draws for it, so a reader meets one glyph per type across the site. To flip to emoji: give each caller an emoji in the icon field and change the i element below to a span with the glyph as its text, one line. The disclosure is a details element with a summary and no script. It has to work on a phone: a title attribute is a hover, which a touch screen does not have and a keyboard reaches unreliably, so the note is one tap or one Enter away, the browser announces it as expanded or collapsed, and a page with no JavaScript still opens it.
